# Genko Studio C++移行・改善 実施計画

版: 1.0 / 2026-10-01 / 開発前の計画案

## 1. 進め方

**C++20＋Qt 6へ段階的に全面移行し、同じ本体で改善を実施する。比較版や使い捨て試作は作らない。** 最初の保存ライブラリから最終製品へ積み上げる。工程中に起動できる状態を保つが、部分完成を安定版として置き換えない。

仕様は`SPEC.md`、受入は`ACCEPTANCE.md`、改善の追跡は`improvements.json`、現行の最低棚卸しは`baseline-inventory.json`に置く。今回作成するのはこれらの文書であり、本体実装は未着手。

## 2. 工程と出口

### M0 契約・台帳・開発環境を固定

依存: 本計画の承認。成果は製品の仕様・CI・テスト資産であり比較試作ではない。

- 固定SHAから操作168種・MCP41道具・4リソース・CLI/HTTP・出力・GUIを照合し、引数と境界条件を台帳化する。静的抽出に出ない動的登録・GUI専用機能を補う。
- 各台帳行へ、旧実装箇所、C++移行先、担当工程、受入ID、状態、証拠を付ける。既存118試験ファイルの各試験について「移植」「契約試験として維持」「内部実装専用なので代替試験へ置換」を理由付きで記録する。件数一致だけで網羅としない。
- 旧v1/v2/v3、承認・履歴・素材・日本語・異常系の合成原稿を保全し、期待される内容と描画を固定する。本番原稿は許可なく使わない。
- C++20、QtのOSS利用可能な具体版、コンパイラ、CMake、第三者ライブラリをロックする。CMakeのRelease/Debug/ASan/UBSan構成、Windows/Linux CIを用意する。CI追加費用が出る場合は停止。
- 参照PCと実ペン・高速度撮影環境、OS別の入力/画面提示計測、正式対応する既存MCPクライアントと版、Windows/Linux実行枠、PSD受取側の既存ライセンス環境、初見操作の確認者を手配できるか確認する。ない項目は担当・確保条件を明示し、合格予定として扱わない。

**出口:** 未割当機能・試験がない台帳、再現可能なビルド、fixture定義、依存ライセンス一覧、受入の実行場所が確定。未確保の実機等があれば、該当最終ゲートは停止中とする。

### M1 原稿モデル・安全な保存・移行器

依存: M0。

- core、CommandBus、ID/単位、v1–v3読込、v4スキーマ、素材ストア、排他、単調増加する確定世代、履歴を実装する。旧原稿の固定コピー、旧履歴→v4状態対応表、履歴参照素材の回収を含め、移行境界を越すUndo/Redoでもv4を維持する。
- `genko new/inspect/doctor`と移行の実用入口を実装し、旧原稿を別フォルダへ変換して読み戻す。Python製coreへ処理を転送しない。
- prepare/commit、原子的置換、履歴・承認監査修復、自動保存・復旧サービスを実装する。保存済み/未保存/失敗等の状態をAPIで提供する。
- 書込不能・容量不足・強制終了・競合・破損入力をテストし、既存データを壊さないことを先に確認する。保存途中失敗から再起動なしの再試行、Undo後の古いbase_revision拒否、旧writer/GCとの変換競合も必須とする。

**出口:** AC-DATA、AC-SAVEの基盤試験合格。すべての旧フィールドを保持できない原稿を編集可能として開かない。画面がない段階でも実ファイルで復旧を検証する。

### M2 C++ GUIと低遅延キャンバス

依存: M1。

- Qt Widgetsの原稿起動、ページ・レイヤー・基本道具、ペン入力、IME入口を実装する。実製品のapp/render層として残す。
- ライブ描線、変更タイルだけの再描画、ワーカーの世代管理、頁の必要時読込を実装する。線確定、Undo/Redo、移動・拡大縮小を同じcoreへ接続する。
- 保存状態・終了保護・別名保存・復旧案内をGUIへ接続する。閉じる操作を先に安全化する。
- 組込み素材のプレビュー事前生成、永続キャッシュと必要時読込を導入し、起動時全素材計算をなくす。
- 1024×640の開始案内、初期プレビュー、長い保存先の表示に使う共通UI部品を実装する。

**出口:** 開く→描く→Undo→保存→終了→別プロセスで再開がC++のみで成立。AC-PERFの入力・基本操作を計測（実ペン・240fps撮影は実施不要。注入した入力での内部時間で測る。`ACCEPTANCE.md` §6）。未移植の機能があるため安定版置換はしない。

### M3 描画・レイヤー・素材の移行と紙質改善

依存: M2。複数作業を行う場合もcore/renderの変更責任を分ける。

- 既存ブラシ、筆圧・回転、消去、塗り、色混ぜ、選択、変形、線編集を移す。
- レイヤー、マスク、合成、補正、フィルター、トーン、効果線、定規、3Dを移す。
- 紙質画像の取込、設定、再現可能な描線、解析可能な期待値fixtureと原寸基準画像、プリセット保存を追加する。旧ブラシの挙動を紙質追加で変えない。
- 素材、ブラシ、ABR等の現行読込範囲、アニメーション、タイムラプス、外部プラグイン互換RPCを移す。必要な動画外部依存とライセンスを記録する。

**出口:** 該当操作台帳・実GUI・保存再開・出力への反映が合格。紙質を別PCへ持ち出して再現できる。記録済みの入力系列（筆圧・傾きを含む）の注入で欠落・停止・筆圧異常がない（実ペンでの確認は実施不要。`ACCEPTANCE.md` §6）。

### M4 写植・原稿出力・編集可能PSD

依存: M1–M3の安定したモデル/描画/文字インターフェース。

- 縦横書き、禁則、縦中横、部分書式、傍点、フキダシ、効果文字、ページ・表紙・見開き・ノンブルを移す。
- ルビの書体・倍率・揃え・間隔、範囲追従を追加する。IME、長文、同じ語の繰返し、再編集を試験する。
- 全出力形式とPSD/PSB読込を移す。下描き除外、トーン、用紙/DPI/色管理を確認する。
- 編集可能PSDの本文・ルビ・フキダシを仕様通りに分離し、必須対応属性を画像化せず保持し、仕様で許容した未対応装飾だけを出力前に説明する。
- ~~PhotoshopとCLIP STUDIO PAINTで実際に文字列を直し、再保存・再読込する。~~ 実施不要（利用者判断、`ACCEPTANCE.md` §6）。代わりに PSD 仕様に沿った文字層の構造検査と Krita での読込を行い、受取アプリでの再編集は未確認として既知制限に書く。購入や認証取得を自動実行しない。

**出口:** AC-TEXT、AC-PSD、AC-EXPORTの全項目合格（受取アプリでの再編集は実施不要として `waived` と記録し、合格に数えない）。

### M5 Studio・MCP・HTTP・CLI

依存: M1、M3、M4で必要な制作コマンドが完成。

- 企画書、脚本、ネーム、生成依頼、参照画像、候補採用、領域、仕上げ、承認、相談、履歴を移す。
- 41のMCP道具と4リソース、CLIとHTTPを同じC++サービスへ接続する。自分の変更だけのUndo、固定欄、人の承認、session分離、path/Host/Origin/authを維持する。
- 接続状態・テスト要求・依頼先・確認待ち・失敗原因を画面化する。複数行返信、送信前確認、下書き保持を追加する。
- 外部クライアント設定の変更案とバックアップを提示し、利用者確認後だけ反映する。生成AIへの実依頼・課金は別承認。

**出口:** 公式MCP SDKのクライアント（stdio・HTTP）、CLI、HTTPから同じ原稿へ安全に操作できる。GUI案内から初回クライアント設定（変更案・バックアップ・確認まで）・再接続・原稿/会話選択・依頼・承認・結果反映まで完走する（利用者のクライアントでの初回導入は実施不要。`ACCEPTANCE.md` §6）。合成画像によるオフライン8ページ工程が完走し、速度・権限・保存に合格する。実生成の画質評価ではない。

### M6 導入・ヘルプ・制作導線・配布候補

依存: M2–M5。

- Windows/Linuxの利用者向け配布を作り、Python/uv/開発環境のない環境で起動・保存・出力を確認する。
- 日本語の開始案内、操作後の次の導線、実メニュー連動ヘルプ、長いパス、初回プレビュー、表示倍率を仕上げる。
- ファイル関連付け・genko://・設定引継ぎは利用者確認付き。旧版と候補版の設定を混ぜず、アンインストールで原稿を削除しない。
- SBOM、ライセンス、対応OS、署名の有無、既知制限、旧版へ戻す手順を付ける。

**出口:** クリーン環境導入、AC-UX、AC-PACKAGEに合格した配布候補がある。本番配布や旧版置換はまだ行わない。

### M7 総合受入・切替

依存: M0–M6とすべての改善項目が完了。

- 台帳の全対象、受入ID、証拠を機械集計。未実施、失敗、重大レビュー指摘を残して完了宣言しない。
- 安全性、2時間連続制作（入力の注入による）、IME（入力メソッドイベントの注入）、全出力、MCP SDKクライアントでの外部接続を最終配布物で実施する。実ペン、PSD受取アプリでの再編集、利用者のクライアント、初見の課題完走は実施不要（`waived`。`ACCEPTANCE.md` §6）。
- 読取専用の独立レビューを受け、実装担当と別にHermesが再現・修正確認・最終判定する。
- 承認された配布範囲内で、まず候補版を別インストール先へ導入する。利用者確認の後に既定起動先を切り替え、旧版・原本・移行前バックアップは保持する。

**出口:** 全必須条件合格、利用者がC++版で制作を継続できる。これを「移行完了」とする。単なるコンパイル成功やPython依存を残したUI置換を完了としない。

## 4. 順序・担当・開発単位

主経路はM0→M1→M2→M3→M4→M5→M6→M7。出力仕様の整理、ヘルプ素材、CI整備等は依存インターフェースが固定された範囲だけ並行可。並行化のために別の性能比較版を作らない。

Hermesが調査、設計、統合、独立受入、コミット・マージ・納品を担当する。将来実装が承認された場合だけ、公式Claude Codeへ境界が固定された実装を委任できる。最初は1作業者で準備確認、並列は非重複worktree、予算内、時間・ターン上限付き。レビュー担当は読取専用で修正・公開・子エージェントを行わない。認証情報・本番原稿へアクセスさせず、上限到達で停止する。

実装PRは「保存と復旧」「ブラシと紙質」「組版とルビ」等の完結した変更に分ける。単体テスト→実ファイル→実GUI/API→受入→レビュー→統合を通す。承認や性能試験を移植の都合で無効化しない。

## 5. 日程と停止条件

開始日は本計画の承認後。現時点では全面移植の実績がないため、完成日や人日を確定値として記載しない。M0終了時に**比較開発なしで**台帳の作業量、依存関係、実行可能な作業者数から各工程の見積幅と日程を確定する。以後は工程出口ごとに残作業と阻害条件だけを更新する。

無期限の調査工程は置かない。M0の成果は契約・環境・担当割当・見積に限定し、言語選択のやり直しを行わない。技術制約を見つけた場合は、C++版での解決方法と影響する要求を提示する。無断でPython中心へ戻したり機能を削ったりしない。

次は停止条件であり、勝手に解消してはいけない。

- 新費用、Qt商用契約、署名購入、外部サービス登録、権限追加が必要。
- 原稿欠損、承認回避、秘密情報漏えい、復旧不能な保存不整合。
- 現行公開契約または保持機能の変更が必要。

実ペン/Windows実機/PSD受取先/初見利用者/利用者の外部クライアントによる試験は、利用者の判断（2026-10-02）で実施不要とした（`ACCEPTANCE.md` §6）。これらの未確保を理由に止めない。

## 6. 戻し方

開発途中は既存Python版・既存原稿をそのまま残す。C++候補版は別設定、別の移行済み原稿で動く。問題時はC++版を閉じ、既存Python版で**移行前原本**を開く。

C++版で追加した編集を旧Python版が読めるとは保証しない。その差分はv4原稿とPNG/PDF等の救出出力で保持する。「旧版へ戻せば新しい編集もそのまま戻る」と案内しない。必要なら人の確認後に受渡し可能な形式で救出する。不可逆な原本上書きや自動ダウングレードは行わない。

## 7. 完了報告の形式

各工程では、実装済み範囲、合格した受入IDと証拠、未実施の環境条件、次の工程を短く報告する。最終報告には配布物、ビルドのコミット、依存版、対応OS、性能の実値、移行手順、残る制限を付ける。速くなる予想やテストの件数を完成した制作体験の代わりにしない。
