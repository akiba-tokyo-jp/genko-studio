# WebAssembly のフィルタープラグイン（ABI v1）

C++ 版 Genko の拡張です（SPEC.md COMP-04・PROD-01、PC5 J-f）。上流 PhotoCraft v0.2.0 のプラグイン（`docs/plugins.md` の ABI v1）と同じ形の **WebAssembly のモジュール（.wasm）** を、フィルター `plugin:<キー>` として使えます。上流で作った .wasm がそのまま動きます（試験は上流の `invert.wasm` を使います）。1 つの .wasm が Windows・Linux（・macOS）で同じに動きます。

## 置き方

```
<設定フォルダー>/plugins/<キー>.wasm
<追加のプラグインフォルダー>/<キー>.wasm   （環境設定 → プラグイン… で使うと決めたとき）
```

- `<キー>` はファイルの名前（拡張子なし）です。`_` か `.` で始まる名前は一覧に出しません。フォルダーの中のフォルダーは見ません。
- 同じキーのプラグインは、`<キー>.py`（Python）→ `<キー>/plugin.json`（ネイティブ）→ プラグインのフォルダーの `<キー>.wasm` → 追加のプラグインフォルダーの `<キー>.wasm` の順に先のものを使います。後のものは「同じ名前のプラグインが先にあります」として一覧に出し、選べません。
- 入れ方: フィルター → プラグイン ▸ プラグインをインストール…、編集 → 環境設定 ▸ プラグイン… の「インストール…」、`genko plugins install <ファイル.wasm>`。どれもプラグインのフォルダーに写すだけで、**動かす設定にはしません**。
- 取り除き方: 環境設定 → プラグイン… の「取り除く」、`genko plugins remove <キー>`（プラグインのフォルダーのファイルと、選んだ記録を消します。追加のプラグインフォルダーのものは、そのフォルダーから人が取り除きます）。
- 読み直し: 環境設定 → プラグイン… の「読み直す」、`genko plugins reload`（覚えたものを忘れて読み直し、選んだモジュールの manifest を読み直します。使えないものは理由を出します）。

## 動かすまで

- プラグインは最初は使いません。「プラグインを使う」をオンにし、一覧でモジュールにチェックを付け、確かめの問いに「はい」と答えたものだけが動きます。
- 一覧を出すときは、.wasm のファイルの名前と大きさ（と、先頭の `\0asm`、32 MB を超えないか）を見るだけで、**何も動かしません**（プラグインを使う設定のときだけ、バイトの sha256 も計ります）。拡張子は小文字の `.wasm` だけを使い、`foo.WASM` のように大小だけ違うものは使えないものとして出します。名前・版・作者・設定（manifest）はモジュール自身が言うものなので、選んだ後に読みます。
- 選んだときの .wasm のバイト（sha256）を覚えます。変わったら動かさず、選び直してもらいます。動かすたびにバイトを読み直して照らし、照らしたのと同じバイトを動かします。
- AI（MCP）・HTTP・制御チャンネルには、プラグインを入れる・選ぶ・同意する入口がありません。MCP の `inspect` の `plugins` で一覧を読むことだけができます。

## どこで動くか（サンドボックス）

モジュールは Genko の中では動きません。Genko と同じフォルダーの別のプログラム **`genko-plugin-host`**（`native/wasm-host`。上流 PhotoCraft の `crates/plugins` の manifest と実行の部分を Rust のまま写したもの）が、上流と同じ WebAssembly のインタープリター **wasmi 2.0.0** で動かします。Genko とは標準入力・標準出力で話します（プロトコル 2、下）。ホストが落ちても止まるのはホストだけで、アプリと原稿は無事です。

| 上限 | 値（上流 `Limits` の既定と同じ） | 超えたとき |
|---|---|---|
| 外の機能（輸入） | なし: WASI・ファイル・ネット・時計・乱数を渡さない | 読み込みで断る |
| モジュールの大きさ | 32 MiB | 断る |
| 線形メモリ | 1 インスタンスに 512 MiB | `memory.grow` が −1 を返す。初めから大きいものは断る |
| 命令の数（燃料） | 1 回の呼び出しに 5000 万、`pc_filter` は 1 標本ごとに 4000 を足す | 「命令の数の上限を超えたため止めました」 |
| 時間 | 1 回の実行（全部の帯）で 60 秒（2000 万命令ごとに確かめる） | 「時間の上限を超えたため止めました」 |
| 呼び出しの深さ | 1024 | トラップ |
| モジュールの形 | wasmi の厳しい上限（関数 1 万個まで、メモリ 1 つ ほか） | 断る |

- 帯ごとに新しいインスタンスで動かすので、帯の間で状態は残りません。
- 上限の値は上流と同じです（同じ wasmi なので、命令の数え方も同じです）。
- wasmi は portable（ループ）の呼び出しで組みます（長く動くモジュールがホストのスタックをあふれさせないため。上流と同じ）。
- Genko の側でも、1 回の実行に 800 万画素ごとに 120 秒の上限（ネイティブのプラグインと同じ）と、書き戻す量の上限を持ちます。

## ABI v1（上流と同じ）

輸入の無いコアの WebAssembly のモジュールで、次を書き出します（整数は注が無ければ `i32`、ポインターはモジュールのメモリの中の位置）。

| 書き出し | 形 | 意味 |
|---|---|---|
| `memory` | メモリ | モジュールの線形メモリ |
| `pc_abi_version` | `() -> i32` | `1` を返す |
| `pc_manifest` | `() -> i64` | manifest の JSON（UTF-8、64 KiB まで）の `(長さ << 32) \| 位置` |
| `pc_alloc` | `(size) -> ptr` | ホストが書ける `size` バイトの場所。足りなければ `0`。帯ごとに新しいインスタンスなので解放は要らない |
| `pc_filter` | `(buf, buf_len, width, height, channels, format, params, params_len) -> i32` | 画素をその場で変える。`0` が成功、ほかは誤りのコード |

### manifest

```json
{"id": "org.example.tone", "name": "Tone", "version": "1.0.0", "kind": "filter", "author": "Example",
 "description": "What it does.",
 "params": {"amount": {"type": "number", "min": 0, "max": 100, "default": 50},
            "steps": {"type": "int", "min": 1, "max": 16, "default": 4},
            "mono": {"type": "bool", "default": false},
            "mode": {"type": "choice", "options": ["soft", "hard"], "default": "soft"}},
 "overlap": 0, "area": "content"}
```

- `id`: `A-Z a-z 0-9 . _ -` の 1〜64 字。`name`: 1〜64 字の名前（Genko のフィルターの一覧に出す名前）。`kind`: `"filter"` だけ。
- `params`: 書いた順。名前は `[A-Za-z0-9_]`（`_` で始まらない。`id`・`layer` でない）。ホストが動かす前に確かめます: 無い値は既定、数は範囲に切る（`int` は丸める）、型の違う値・選択肢に無い値は断る。Genko のフィルターの窓は `number`・`int` を数の欄、`bool` を 0〜1 の欄で聞き（0.5 以上が true）、`choice` は既定のまま渡します。
- `overlap`（0〜256）: 出す画素の周りに要る画素の数（ぼかしの半径など）。ホストは帯の四方をその分広げ（絵の端は端の画素をくり返す）、結果の内側だけを使います。
- `area`: `"content"`（既定。層の見えている画素の箱を `overlap` だけ広げた所）か `"canvas"`（透明な所も含めたページ全体。生成するもの）。

### 画素

`buf` は `width × height × channels` の **リトルエンディアンの `f32`** の標本です（行ごと、画素ごとにチャンネルを並べる）。どの深さでも 0〜1 に正規化し（32 bit は 1 を超えることがある）、文書の色モデルのまま渡します（変換しません）。

`format = 深さ | アルファ << 8 | モード << 16`

- 深さ（ビット 0〜7）: 8・16・32（参考。標本はいつも `f32`）。
- アルファ（ビット 8）: 最後のチャンネルがアルファ（掛け合わせていない）のとき 1。
- モード（ビット 16〜23）: PSD の番号。0 2 階調・1 グレー・3 RGB・4 CMYK・7 マルチチャンネル・8 ダブルトーン・9 Lab。

Genko での中身:

| 層 | チャンネル | 深さ | 値 |
|---|---|---|---|
| 8 bit のペイントレイヤー | RGBA | 8 | sRGB（プロファイルのあるページはページの値）を 255 で割った値 |
| 高精度のレイヤー（16・32 bit の RGB のページ） | RGBA | 16・32 | ページの RGB の値（そのプロファイルの符号化した値。32 bit は 1 を超えることがある） |
| インキのページのレイヤー（CMYK・Lab・グレー・マルチチャンネル） | 色の版とアルファ | ページの深さ | CMYK は 0 がインキなし・1 がベタ、Lab は ICC の符号化（L は 0〜1、a・b は 0.5 付近が 0）、グレーは明るさ（0 が黒） |
| アルファチャンネル・クイックマスク・レイヤーマスクの編集 | グレー 1 つ（アルファなし） | 8 | 濃さ（1 が選択・不透明） |

戻ってきた値のうち、NaN・無限は元の値に戻し、8・16 bit の値とアルファは 0〜1 に切ります。選択範囲があるときは Genko が `元 + (結果 − 元) × 覆い` で混ぜます（組込みのフィルターと同じ。プラグインは選択範囲を知りません）。

### 設定と `_image`

`params` は `params_len` バイトの UTF-8 の JSON です。確かめた設定と、帯の場所 `_image` が入ります。

```json
{"amount": 50, "mode": "soft",
 "_image": {"x": 0, "y": 256, "width": 1024, "height": 256, "overlap": 0,
            "canvasWidth": 6000, "canvasHeight": 4000,
            "mode": "rgb", "depth": 8, "alpha": true, "channels": 4}}
```

`x`・`y` は帯（余白を含む）の左上がページのどこか（画素）です。場所で変わるフィルター（グラデーション・周辺の減光など）も帯の継ぎ目が出ません。

## プロトコル 2（Genko と genko-plugin-host）

1 回の実行に 1 つのホストを起動し、標準入力・標準出力で 1 行の JSON とそのバイトをやりとりします。

1. Genko → `{"protocol": 2, "module": N}` と、モジュールの N バイト（照らしたバイト）。ホスト → `{"ok": true, "manifest": {…}, "limits": {…}, "host": "genko-plugin-host 0.1.0 (wasmi 2.0.0)"}`、または `{"ok": false, "error": "…", "code": "module" | "abi" | "manifest" | "trap" | "limit" | …}` で終わる。
2. Genko → 帯ごとに `{"protocol": 2, "width", "height", "channels", "format", "params"}` と標本。ホスト → `{"ok": true, "width", "height", "channels"}` と標本、または断りで終わる。
3. Genko が標準入力を閉じる → ホストが終わる。

帯は、ページの上の 256 画素の格子にそろえた 1 タイルの高さで、約 4 MiB（f32）に収まるだけ横に並べたものです（上流 `apply.rs` と同じ）。帯が（余白を含めて）プラグインのメモリの半分に収まらなければ断ります。同じ帯の形はネイティブのプラグインのプロトコル 2（`docs/PLUGIN_NATIVE.md`）でも使います。

## スマートフィルター

スマートオブジェクトにプラグインのスマートフィルターを足せます（フィルター → プラグイン のフィルターを、スマートオブジェクトを選んで使う）。プラグインが入って選ばれている間は、描くたびにプラグインで描き直します。スマートフィルターを足す・直す・動かす・消すたびに、そのフィルターまでの絵を原稿に残し（`plugin-filters@1` の `kept`）、プラグインが無い・選ばれていない・変わった・動かせないパソコンでは、残した絵で見せます（見えを変えません）。

## 作る人へ

- Rust: 上流の `examples/plugins/invert-rs`（`no_std`、アロケーターなし、1 KiB に満たない）が完全な例です。`cargo build --release --target wasm32-unknown-unknown`。
- C・Zig・AssemblyScript・WAT でも、輸入の無いコアのモジュールなら動きます（Rust なら `no_std` か、WASI に触れない `std`）。
- 試験の資産は `native/tests/data/plugins/`（WAT の元と .wasm）。WAT から .wasm にするには `native/wasm-host` で `cargo run --example wat2wasm -- in.wat out.wasm`（プラグインとして読めるかも確かめます）。
- 解釈実行なので 1 命令あたり本体の 10〜100 倍遅く、画素ごとの処理や小さな近傍の処理に向きます。Genko は帯を順に流します（ホストは 1 つ）。

## v1 に無いもの

パネルや画面を持つプラグイン、ほかの層や原稿を読むプラグイン、ホストからの呼び戻し（進み具合・取り消し。Genko は取り消されると帯の間でホストを止めます）、ファイル形式のプラグイン。

## 組み方（Genko を組む人へ）

- `native/wasm-host` は CMake が cargo で組み（`cargo build --release --locked`。版は `Cargo.lock` の checksum で確かめる）、genko と同じフォルダーに置きます（`native/cmake/GenkoPluginHost.cmake`）。cargo が無い・組めないときは警告だけ出し、WebAssembly のプラグインだけが使えません（ほかは今のまま組めます）。`-DGENKO_BUILD_PLUGIN_HOST=OFF` で組みません。組めなかったときも印を残すので、網の無い機械で組み直すたびに cargo が網を探して待つことはありません（`Cargo.toml`・`Cargo.lock`・ソースが変わったとき、作り直しの構成のときにもう一度組みます）。ホストは genko の隣のものだけを使い、環境変数では選べません（試験は試験の口で渡します）。
- CI は `tools/ci/build_wasm_host.sh`（crates.io から取って組み、ホストの試験 `cargo test` を流す）。
- Windows も同じ cargo（MSVC の道具）で組みます（`genko-plugin-host.exe`。実機での確かめは統合の後の Windows の作業）。vcpkg は使いません。
