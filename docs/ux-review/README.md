# UI/UX 総点検（2026-09）

対象は人が触る Genko Studio の画面（PySide6 のデスクトップアプリ）。AI が MCP で作業している最中と後に、人が見守り・指示し・直す体験を含む。
画像生成は使っていない（キーが無く、承認で「絵を使わない案」に決まった）。Windows・Mac の実機は未確認で、この点検は
Linux の画面なしの Qt（offscreen）で撮ったスクリーンショットと、コードから行った。

- 用語集: [glossary.md](glossary.md)
- 画像生成の記録: [assets.md](assets.md)（使っていない）
- スクリーンショット: [screenshots/before](screenshots/before)、[screenshots/after](screenshots/after)

| 項目 | 内容 |
|---|---|

## MCP への提案（UI とは別枠・実装しない）

- 道具の返事で、コマの `slot` と画面の「コマ番号」（読み順）を並べて返すと、人と AI が同じ番号で話せる。
- 「AI に何を許すか」（削除・上書き・書き出し）の設定を、人が画面で変えられる仕組み（U-17）。

### 残った課題

- U-05・U-12（AI の変更の強調・まとめて差し戻し・入らなかった操作の再実行）は範囲外にした。
- U-17（AI に何を許すかの画面の設定）は機能の追加になるため提案のまま。
- 1366×768 では右の列が 3 段になり、レイヤーの一覧は数行になる（スクロールで見る）。
- Windows・Mac の実機での見え方（フォント、Qt の日本語訳、表示倍率、OS の「動きを減らす」）は未確認。
- テスト: 全体 801 件のうち 800 件が通過。`test_h1.py::test_a_thick_book_stays_quick`（厚い本を 3.0 秒以内に開く）が
  全体実行のときだけ 3.08 秒で落ちる。単独では 3 回とも通過し、変更前でも同じ環境で 3.9 秒で落ちることがあった。
  今回の追加分が開く時間に足すのは約 0.04 秒（計測）。

## 仕上げ（見た目をオシャレなツールの水準へ：P1〜P5）

Figma・Linear・Procreate・CLIP STUDIO と並べて見たときの差（右の列の詰め込み、文字の段の少なさ、余白の不揃い、
部品の仕上げ、フォームのような起動画面）を、機能・保存形式・ショートカットを変えずに詰めた。

| 番号 | 変えたこと | 場所 |
|---|---|---|
| P1 | 右の列を「承認待ち（待つものがあるときだけ上に出る）＋ 1 段のタブ（レイヤー・台詞・ページ・カラー、AI の本ではコマの詳細）」に。履歴・素材・定規・3D・点検・資料は「ウィンドウ」から開くと同じ列に並ぶ。テキストの道具で台詞、描く道具でレイヤーのタブが前に出る。状態の行の「承認箱 N」を押すと承認待ちが出る | `main.py`（`_sync_box`・`_fit_box`・`_panel_for_tool`） |
| P2 | 文字を 4 段に：見出し（パネル・道具の名前、太字で大きめ。ダイアログの題はさらに大きく）・本文・補足（説明と区切りの名前、灰色）・数字（件数、太字） | `theme.py` |
| P3 | 余白を 8px 単位に（ボタン・一覧の行・タブ・入力欄・ツールの設定）。承認待ちの一覧は行の数だけの高さ。ツールの設定は今の道具のページの高さだけになり、短いページの横に出ていたスクロールバーが消えた | `theme.py`・`tool_settings.py`・`studio_widgets.py` |
