# UI/UX 総点検（2026-09）

対象は人が触る Genko Studio の画面（PySide6 のデスクトップアプリ）。AI が MCP で作業している最中と後に、人が見守り・指示し・直す体験を含む。
画像生成は使っていない（キーが無く、承認で「絵を使わない案」に決まった）。Windows・Mac の実機は未確認で、この点検は
Linux の画面なしの Qt（offscreen）で撮ったスクリーンショットと、コードから行った。

- 用語集: [glossary.md](glossary.md)
- 画像生成の記録: [assets.md](assets.md)（使っていない）
- スクリーンショット: [screenshots/before](screenshots/before)、[screenshots/after](screenshots/after)

## Phase 0：現状

| 項目 | 内容 |
|---|---|
| 形態 | デスクトップアプリ（Python・PySide6/Qt6）。Windows・Mac・Linux |
| 見た目の土台 | `app/theme.py` の `Tokens`（明・暗）＋ Qt のスタイルシート。Lucide の SVG アイコン、IBM Plex Sans JP 同梱、ダイアログは `app/dialog_look.py` |
| 文言 | コードの中に日本語で直接。エラー文の日本語化は `app/wording.py` |
| MCP | `src/genko/mcp/server.py`（stdio、道具 40 ほど）と HTTP の `genko serve`。AI の変更は原稿ファイルの見張りで約 0.5 秒で画面に出る。人の道具・ページ・表示は奪わない |
| 確かめた画面 | 1366×768 / 1920×1080 / 2560×1440、表示倍率 100 / 125 / 150%、明・暗。本体、承認箱、空の原稿、起動画面、新しい原稿、原稿用紙、書き出し、環境設定、絵柄を選ぶ |
| AI の再現 | テスト用の偽のエージェント（`tests/agents/fake_agent.py`）が MCP の道具だけで 4 ページの本を作った状態と、作画の承認待ちの状態。画面を開いたまま AI に台詞を直させた |

### 代表タスク（推定を含む）

| タスク | 手数・迷う点 |
|---|---|
| A. AI に描かせる | 接続はアプリの外で JSON を手で書く（説明は docs/OTHER_AGENTS.md だけ）。画面に接続の状態が出ない。進み具合は状態の行のバッジと承認箱。1 コマを指すとき、画面の「コマ番号」と AI の識別子を結ぶ手段が無い。台詞の手直し・書き出しは迷いにくい |
| B. 手描き | 新しい原稿（2 手）→ コマ割り → ペン → テキストの道具で縦書き → ページ一覧で並べ替え → 書き出し。大きく迷う所は無い |
| C. 併用 | AI の保存で人の道具・ページ・選択は変わらない。重なった操作は「入りませんでした」が 6 秒出るだけ |

残すべき良い点：落ち着いた無彩色寄りの配色とトークン、暗い画面の灰色の階調、Lucide で揃ったアイコン（150% でもにじまない）、
Tab で全部隠す・スペース＋ドラッグ・Ctrl＋ホイール・回転・ショートカットの変更、右綴じ・縦書き・禁則・ルビ・縦中横、
仕上がり線・裁ち落とし・基本枠の表示、用途で選ぶ書き出し、日本語の分かりやすいエラー文、AI の変更が約 0.5 秒で出て人の作業を奪わないこと。

## MCP への提案（UI とは別枠・実装しない）

- 道具の返事で、コマの `slot` と画面の「コマ番号」（読み順）を並べて返すと、人と AI が同じ番号で話せる。
- 「AI に何を許すか」（削除・上書き・書き出し）の設定を、人が画面で変えられる仕組み（U-17）。
