# Genko ネームの規則

Genko は、あなた（エージェント）が書いた計画を検査し、コマ割りと縦書きの写植を計算する。
ここに書いた規則を破ると、`issues` に指摘が返る。`severity: "error"` は保存できない。`"warning"` は保存できるが直すのが望ましい。
指摘の `path` は、あなたが送った JSON の中の位置（JSON ポインタ）である。その場所だけを直して送り直す。

## 手順

1. `inspect target=schemas` で入力の形を確かめる。
2. 企画書（bible@1）を `set_bible` に送る。`commit:false` で指摘を見て、なくなったら `commit:true`。
3. 脚本（script@1）を `set_script` に送る。beat ごとに `page` を決める。
4. ページごとに `inspect target=page page=N` でそのページの beat と前後を読み、ネーム計画（name_plan@1）を書く。
5. コマ割りは `layout_ideas` で案の束を出して選び、崩してから `submit_name` に送る（下の「コマ割りの案の束」）。
6. 返ってきたプレビュー画像を見て直す。よければ `commit:true` で保存し、`record_review` で点検結果を残す。
7. `request_approval` で人間にネームの承認を頼む。承認は人間だけができる。待つ間は別のページを進める。
8. 人間の修正指示は `next`（kind `revise_page`）と `tickets` に出る。`submit_name` を `replace:true` で送り直す。

## コマ割りの緩急

コマ割りは格子を埋める作業ではない。ページの中で「どこを見せるか」を大きさと形で決める。

1. **beat の重さでコマの大きさを決める。** そのページの beat を重い順に並べる。いちばん重い 1 つ（見せ場・決めの表情・動きの頂点・場面の初出）に基本枠の 3〜6 割を渡す。軽い beat（相づち・移動・説明）は小さくし、2 つを 1 コマにまとめてもよい。1 ページに大・中・小をそろえる。全部が同じ大きさなら、どこも見せていない。
2. **めくりで見せる。** めくって最初に見えるのは偶数ページの先頭。見せ場（`reveal`）はそこに置き、ページの上半分以上の大ゴマにする（断ち切りも）。奇数ページの最後は引き（`hook`）: 小さく切って間を作るか、縦長のコマで次をめくらせる。
3. **視線の流れを作る。** 目は右上から入り、段の中を右から左へ、段の終わりで次の段の右端へ戻り、左下で抜ける。大ゴマは流れの途中に置くと目が止まる。縦長のコマは段の右端か左端に置く（真ん中に置くと読み順に迷う）。差し込みは宿主の右上（先に読む）か左下（後に読む）。
4. **前のページと割りを変える。** 段の数・大ゴマの位置・コマの数を、隣のページと変える。会話が続くページでも、1 ページに 1 か所は形を崩す（大ゴマ・幅の違う段・広い間）。
5. **崩す道具は使いどころで選ぶ。**
   - 斜め（段・列・行の `tilt_mm`。コマの `slant` も）: 動き・衝撃・緊張。8〜25 mm。会話や静かな場面には使わない。
   - 断ち切り（コマの `bleed: true`）: 広がり・迫力・余韻。紙の端に接するコマだけ。1 ページに 1〜2 か所。
   - 重ね（`insets` で境目をまたぐ）: 大ゴマの上に反応の顔や手元のアップを重ね、同じ瞬間の別の目を見せる。
   - 差し込み（`insets` で宿主の中に収める）: 大ゴマの中の小さな反応・時間が止まった感じ。
   - はみ出し（コマの `overflow: true`）: 枠を破る勢い・人物の存在感。見せ場のコマに 1 か所。
   - 枠なし（コマの `border_mm: 0`）: 回想・心の声・静けさ・余白。
   - 間（`gap_mm`）: 広い間（10〜15 mm）は時間の経過や場面の切れ目、狭い間（2〜4 mm）は続けざまの動きや同時。
6. **定型は例にすぎない。** `template`（`reveal_top`・`reveal_bleed`・`finale_bleed`・`action_slant`・`title_top` など。一覧は `inspect target=page`）は出発点に使ってよい。そのまま並べると単調になるので、`tiers` に書き直して崩す。

## コマ割りの案の束（layout_ideas）

1. `layout_ideas` に `page` と、下書きの計画 `plan`（コマの指示と台詞まで）を渡す。コマ数を省くと `plan` のコマ数ちょうどの案が出る。
   - `preset`: 会話が中心なら `talk`、ふつうは `standard`、動きは `action`、見せ場・扉は `showcase`。
   - `focus`: 見せ場のコマの番号（読み順）。そのコマがいちばん大きい案だけが出る。
   - `knobs`（0〜1）で斜め・断ち切り・重ねなどの多さを上げ下げする。同じ束をもう一度出すときは返った `seed` を渡す。
2. 束（既定 12 案）には、無難な格子・大きさの差が小さい割り（`layout_flat` と同じ基準: 3 コマ以上で、いちばん大きいコマがいちばん小さいコマの 1.5 倍未満）・帯の積み重ね（4 コマ以上で、どの段も 1 コマで斜めが無い。`showcase` を除く）・読み順の崩れ・短辺 25 mm 未満のコマ・2 mm 未満の間・束の中で見た目の似た案（段ごとのコマ数の組・大ゴマの位置・斜め・断ち切り・差し込み・枠なしが同じ）は入らない（除いた数は `dropped`）。目立つ所（10 mm 以上の斜め・断ち切り・差し込みか重ね・大ゴマ〔基本枠の 35% 以上で、2 番目の 1.8 倍以上〕・縦積み・11 mm 以上の段の間・枠なし）が `standard`・`action` で 2 種類、`talk`・`showcase` で 1 種類に足りない案は、12 案のうち 2 案まで。今のページが単調な格子でも、`base_page` の変異には目立つ所が足される。`summary`・`pattern`・`largest` を見て、beat の重さとめくりに合う案を選ぶ。`like_pages` に前後のページが入っている案は、隣と似ている（`layout_repeats` になりやすい）。
3. 崩す: よい案があれば `base` にその `skeleton` を入れ、`variation`（0.2〜0.5）で変えた束を出す。今のページを崩すなら `base_page: true`。
4. 選んだ案の `plan`（`plan` を渡したとき）を、`submit_name` にそのまま送る。案の slot は読み順に p1, p2, … で、案に無い slot のコマは `plan` から外れる（`plan_dropped`・警告 `plan_panels_dropped`。外れたコマの beat と台詞は残りのコマに移す）。自分で入れるときは、`tiers` と `insets` をそのまま入れ、`template` を null にし、`panels` の各 slot に `skeleton.panels` の `bleed`・`border_mm`・`overflow` を足し、`slant` は null にする（斜めは段・列・行の `tilt_mm` に入っている）。
5. 最後はプレビューを見て自分で直す（大ゴマの位置、間、斜めの向き）。案は下書きで、そのまま出さなくてよい。
6. 人が承認したページは変えない（`layout_ideas` は警告 `name_approved`、`submit_name` は断る）。

## 単調さの警告（止めない。直す）

`submit_name` は、ほかの指摘の後にこれらの警告を返す。保存はできるが、次のように直す。

| code | 意味 | 直し方 |
|---|---|---|
| `layout_repeats` | 前後のページと合わせて 3 ページ続けて、段組が同じか似ている | このページの段の数・大ゴマの位置・コマの数を変える。`layout_ideas` で `like_pages` が空の案を選ぶ |
| `layout_flat` | 3 コマ以上で、いちばん大きいコマがいちばん小さいコマの 1.5 倍に届かない | いちばん重い beat のコマを大きくし、軽い beat を小さくまとめる（`focus` を付けて `layout_ideas`） |
| `reveal_beat_small` | 脚本の見せ場（reveal）の beat のコマが小さい | そのコマを大ゴマにする（基本枠の 3 割以上）か、断ち切り・はみ出しで目立たせる |
| `book_without_accent` | コマのある 4 ページ以上に、斜めの境目も断ち切りも 1 つも無い | 見せ場や動きのあるページで、斜め（`tilt_mm`）か断ち切り（`bleed`）を使う |

## 段組（tiers）

- `tiers` は上から下へ並べる。`h` は段の高さの割合で、合計 1.0。
- 段の中の `cols` は **右から左** へ並べる（日本語の読み順）。`w` は幅の割合で、合計 1.0。
- 1つの列を上下に割るときは `rows`（上から下、`h` の合計 1.0）。これより深い入れ子はできない。
- `slot` はコマの名前（例 p1）。`panels` の `slot` と1対1で対応させる。
- 読み順は「上の段から、段の中は右から左、列の中は上から下」。差し込み・重ねのコマは宿主のそばで、位置の順に読まれる。
- 境目ごとの間と斜め（どれも任意）: 段・列・行に `gap_mm`（その後ろの境目の間。0〜100 mm。無ければ計画の `tier_gap_mm`〔既定 7〕・`col_gap_mm`〔既定 3〕）と `tilt_mm`（その後ろの境目の斜め。−80〜80 mm。横の境目は右端が下がる向き、縦の境目は下端が右へ寄る向きが正）。最後の段・列・行に書いたものは使われない（警告 `layout_border_unused`）。
- コマの見た目（どれも任意）: `panels[]` の `bleed`（断ち切り）・`border_mm`（枠線 0〜5 mm。0 で枠なし）・`overflow`（true で絵が枠で切れない）。
- 差し込み・重ね: 計画の `insets: [{slot, on, rect: [x, y, 幅, 高さ]}]`。`on` は段組のコマの slot、`rect` は基本枠の幅・高さを 1 とした位置。`on` のコマの中に収めれば差し込み、境目をまたげば重ね。`insets` のコマも `panels` に指示を書き、コマ数に数える。
- 定型を使うときは `tiers: null` にして `template` に名前を書く。
- 1ページのコマは 1〜8。コマの短辺が 25 mm を切ると警告。

## コマの指示（panels）

- `shot`: ELS（超遠景）/ LS（遠景）/ FS（全身）/ MS（腰から上）/ MCU（胸から上）/ CU（顔）/ ECU（顔の一部）/ INSERT（物のアップ）
- `angle`: eye / high（俯瞰）/ low（あおり）/ bird / worm / dutch
- `characters[].pos`: left / left_third / center / right_third / right。`scale` は人物の大きさ（0〜1）。`facing` は向き。
- 場面（scene）の最初のコマは状況が分かるショット（ELS / LS / FS）にする。
- 同じ `shot` を3コマ以上続けない。
- 同じ場面の2人の左右を入れ替えない（180度ルール）。わざと入れ替えるコマは `cross: true`。

## 台詞（lines）

- 脚本で、そのページの dialogue / monologue / narration の beat は、どこかのコマに **ちょうど1回** 置く。
- `breaks` は縦書きの1行ずつ。1行 14 字まで、フキダシ1つで 40 字まで。自然な切れ目で改行する。
- `balloon`: speech（話す）/ thought（心の声）/ shout / whisper / narration（四角い枠）。
- フキダシはコマの右上から読み順に置かれ、人物の顔の位置を避ける。入らなければ `balloon_overflow` が返るので、台詞を短くするか、コマを大きくするか、台詞を別のコマに移す。
- 話者がそのコマにいないと、フキダシの尾が付かない（画面外の声として扱う）。

## めくり

- 右綴じでも左綴じでも、ページをめくって最初に見えるのは **偶数ページ** である。
- 驚きや見せ場（`reveal`）は偶数ページの先頭に置く。脚本の beat と、ネーム計画の `turn_role: "reveal"` の両方で示す。
- 引き（`hook`）は奇数ページの最後のコマに置く。
- 1ページ目は表紙の次に単独で見えるページ。

## 絵について

- Genko のネームは構図と台詞の設計図である。構図は線のラフ（アタリ）で描く: 人物の位置・向き・大きさ、物や背景の形を、ネームのレイヤーに鉛筆の線で。仕上がった絵は描かず、画像も貼らない（画像は、ネームの承認の後の作画の工程で使う）。
- 台詞・効果音は画像に描かせない。文字は Genko が縦書きで描く。
